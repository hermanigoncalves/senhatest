## 🗄️ 3. Especificação Formal do Esquema de Dados (Data Contracts)

### 3.1. Tabela `public.offices` (Consultórios / Salas de Atendimento)
Armazena os locais físicos de atendimento e define para qual TV as chamadas daquela sala serão roteadas.

| Coluna | Tipo | Constraints | Descrição |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY` | Identificador único da sala |
| `name` | `VARCHAR(100)` | `NOT NULL` | Nome descritivo (ex: "Consultório 01 - Clínica Geral") |
| `code` | `VARCHAR(20)` | `NOT NULL UNIQUE` | Código curto/sigla da sala (ex: "C01", "C02") |
| `location` | `VARCHAR(100)` | `NULL` | Localização física (ex: "Térreo - Ala A", "1º Andar - Ala B") |
| `target_tv` | `VARCHAR(20)` | `NOT NULL DEFAULT '1' CHECK (target_tv IN ('1', '2', 'all'))` | **Roteamento de TV:** `'1'` (TV 01), `'2'` (TV 02), `'all'` (Ambas) |
| `active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Indicador de sala ativa no plantão |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data de criação |
| `updated_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data da última atualização |

### 3.2. Tabela `public.doctors` (Corpo Clínico)
Armazena o cadastro detalhado dos médicos e seu vínculo com o consultório.

| Coluna | Tipo | Constraints | Descrição |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY` | Identificador único do médico |
| `name` | `VARCHAR(150)` | `NOT NULL` | Nome completo do médico (ex: "Dr. Carlos Eduardo") |
| `crm` | `VARCHAR(30)` | `NOT NULL` | Número do registro no CRM (ex: "12345") |
| `crm_uf` | `VARCHAR(2)` | `NOT NULL DEFAULT 'SP'` | UF emissora do CRM |
| `specialty` | `VARCHAR(100)` | `NOT NULL DEFAULT 'Clínica Geral'` | Especialidade médica |
| `phone` | `VARCHAR(30)` | `NULL` | Telefone / WhatsApp de contato |
| `email` | `VARCHAR(120)` | `NULL` | E-mail profissional |
| `office_id` | `BIGINT` | `REFERENCES public.offices(id) ON DELETE SET NULL` | Consultório fixo ou padrão associado |
| `office_name`| `VARCHAR(100)` | `NULL` | Cache do nome do consultório para performance |
| `active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Status operacional do médico |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data de cadastro |
| `updated_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data da última alteração |

### 3.3. Tabela `public.users` (Autenticação e Acessos)
Gerencia as credenciais e o nível de privilégio no sistema.

| Coluna | Tipo | Constraints | Descrição |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY` | Identificador único do usuário |
| `name` | `VARCHAR(150)` | `NOT NULL` | Nome de exibição |
| `username` | `VARCHAR(50)` | `NOT NULL UNIQUE` | Login de acesso único |
| `password` | `VARCHAR(100)` | `NOT NULL` | Senha de autenticação |
| `role` | `VARCHAR(30)` | `NOT NULL CHECK (role IN ('admin', 'receptionist', 'doctor'))` | Perfil de acesso |
| `doctor_id` | `BIGINT` | `REFERENCES public.doctors(id) ON DELETE SET NULL` | Vínculo se o usuário for do tipo médico |
| `active` | `BOOLEAN` | `NOT NULL DEFAULT TRUE` | Conta ativa/inativa |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data de criação |
| `updated_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data de atualização |

### 3.4. Tabela `public.patients` (Cadastro de Pacientes)
Armazena a identificação do paciente encaminhado.

| Coluna | Tipo | Constraints | Descrição |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY` | Identificador único do paciente |
| `name` | `VARCHAR(150)` | `NOT NULL` | Nome completo do paciente |
| `document` | `VARCHAR(30)` | `NULL` | CPF ou documento de identificação |
| `phone` | `VARCHAR(30)` | `NULL` | Telefone de contato |
| `birth_date`| `DATE` | `NULL` | Data de nascimento |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Data de registro |

### 3.5. Tabela `public.patient_calls` (Fila Nominal e Histórico com TV de Destino)
Controla o ciclo de vida do atendimento e o roteamento das chamadas na TV.

| Coluna | Tipo | Constraints | Descrição |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY` | Identificador sequencial da chamada |
| `call_id` | `INT` | `NOT NULL DEFAULT 1` | ID incremental da chamada para a TV |
| `patient_id` | `BIGINT` | `REFERENCES public.patients(id) ON DELETE SET NULL` | Chave estrangeira do paciente |
| `patient_name`| `VARCHAR(150)`| `NOT NULL` | Nome do paciente anunciado na TV |
| `doctor_id` | `BIGINT` | `REFERENCES public.doctors(id) ON DELETE SET NULL` | Médico responsável |
| `doctor_name`| `VARCHAR(150)`| `NOT NULL` | Nome do médico exibido na TV |
| `office_name`| `VARCHAR(100)`| `NOT NULL` | Nome do consultório anunciado |
| `target_tv` | `VARCHAR(20)` | `NOT NULL DEFAULT '1' CHECK (target_tv IN ('1', '2', 'all'))` | **TV de Destino:** `'1'` (TV 01), `'2'` (TV 02), `'all'` (Ambas) |
| `type` | `VARCHAR(30)` | `NOT NULL DEFAULT 'Normal' CHECK (type IN ('Normal', 'Preferencial', 'Retorno'))` | Prioridade do atendimento |
| `status` | `VARCHAR(30)` | `NOT NULL DEFAULT 'waiting' CHECK (status IN ('waiting', 'called', 'in_progress', 'completed', 'absent', 'cancelled'))` | Estado do atendimento |
| `created_by_user` | `VARCHAR(100)` | `NULL` | Identificação de quem cadastrou (Recepção) |
| `called_at` | `TIMESTAMPTZ` | `NULL` | Momento em que o médico disparou a chamada na TV |
| `finished_at`| `TIMESTAMPTZ` | `NULL` | Momento de conclusão da consulta |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Momento em que o paciente entrou na fila |

## ⚡ 4. Índices de Desempenho & Otimização

Para garantir que as TVs e os Painéis dos Médicos recebam respostas em **menos de 50 milissegundos**, criamos os seguintes índices B-Tree:

```sql
-- 1. Otimiza a consulta da TV filtrando por target_tv e ordenando por id decrescente
CREATE INDEX IF NOT EXISTS idx_patient_calls_target_tv ON public.patient_calls (target_tv, status);
CREATE INDEX IF NOT EXISTS idx_patient_calls_called_desc ON public.patient_calls (called_at DESC NULLS LAST);

-- 2. Otimiza a fila do médico filtrando por doctor_id e status ativos
CREATE INDEX IF NOT EXISTS idx_patient_calls_doctor_status ON public.patient_calls (doctor_id, status);

-- 3. Otimiza listagem de médicos e consultórios ativos para a Recepção
CREATE INDEX IF NOT EXISTS idx_doctors_active ON public.doctors (active);
CREATE INDEX IF NOT EXISTS idx_offices_active ON public.offices (active);

-- 4. Otimiza autenticação de login por username
CREATE INDEX IF NOT EXISTS idx_users_username ON public.users (username);
```

## 🛡️ 5. Segurança & Políticas de Row Level Security (RLS)

O Supabase terá RLS ativado em todas as tabelas públicas, permitindo leitura e escrita com integridade garantida pelo backend:

```sql
ALTER TABLE public.offices ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.doctors ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.users ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.patients ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.patient_calls ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.tickets ENABLE ROW LEVEL SECURITY;

-- Políticas de Leitura
CREATE POLICY "Leitura Geral Offices CMIP" ON public.offices FOR SELECT USING (true);
CREATE POLICY "Leitura Geral Doctors CMIP" ON public.doctors FOR SELECT USING (true);
CREATE POLICY "Leitura Geral Users CMIP" ON public.users FOR SELECT USING (true);
CREATE POLICY "Leitura Geral Patients CMIP" ON public.patients FOR SELECT USING (true);
CREATE POLICY "Leitura Geral PatientCalls CMIP" ON public.patient_calls FOR SELECT USING (true);
CREATE POLICY "Leitura Geral Tickets CMIP" ON public.tickets FOR SELECT USING (true);

-- Políticas de Escrita
CREATE POLICY "Escrita Geral Offices CMIP" ON public.offices FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "Escrita Geral Doctors CMIP" ON public.doctors FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "Escrita Geral Users CMIP" ON public.users FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "Escrita Geral Patients CMIP" ON public.patients FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "Escrita Geral PatientCalls CMIP" ON public.patient_calls FOR ALL USING (true) WITH CHECK (true);
CREATE POLICY "Escrita Geral Tickets CMIP" ON public.tickets FOR ALL USING (true) WITH CHECK (true);
```
