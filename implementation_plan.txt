## 1. Objetivo Declarativo & Visão Geral

### 🎯 Objetivo Único
Prover uma plataforma web completa de atendimento médico sem triagem para o **Centro Médico Integrado Piratininga (CMIP)**, permitindo à Recepção encaminhar pacientes diretamente para o médico selecionado, aos Médicos gerenciarem seus atendimentos e dispararem chamadas por voz (TTS em PT-BR) com roteamento seletivo para **Duas Telas de TV independentes (TV 01 e TV 02)** parametrizadas pelo Administrador no cadastro de cada consultório, e à Administração gerenciar o CRUD completo de Médicos, Consultórios, Usuários e Filas.

### 📐 Limites de Escopo (In-Scope vs Out-of-Scope)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ✅ IN-SCOPE (Fazer Agora - Entregáveis Críticos):                            │
│ 1. Roteamento Multi-TV (TV 01 e TV 02 com filtro de áudio e visual)        │
│ 2. CRUD Completo de Médicos no AdminPanel (Nome, CRM, UF, Especialidade,    │
│    Consultório, Login automático, Status Ativo/Inativo, Exclusão)           │
│ 3. CRUD de Consultórios com seleção de TV de Destino (TV 01, TV 02, Ambas) │
│ 4. CRUD de Usuários com papéis ('admin', 'receptionist', 'doctor')          │
│ 5. Recepção com listagem dinâmica de médicos ativos e envio em tempo real   │
│ 6. Painel do Médico com fila ordenada (Preferencial no topo) e ciclo de vida│
│ 7. Painel da TV com identificador dinâmico (?tv=1 / ?tv=2) e fila FIFO áudio│
│ 8. APIs Serverless Vercel (api/medical.js) e Banco Supabase com RLS         │
├─────────────────────────────────────────────────────────────────────────────┤
│ ❌ OUT-OF-SCOPE (Fora de Escopo - Fases Posteriores):                       │
│ • Integração SOAP/REST com prontuários eletrônicos legados (Tasy, MV Soul)  │
│ • Emissão de guias de faturamento TISS/TUSS                                 │
│ • Gateway de pagamento de consultas no totem                                │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. Arquitetura do Sistema & Roteamento Multi-TV

### 🔄 Fluxo de Roteamento da Chamada para a TV Correta

```mermaid
sequenceDiagram
    autonumber
    actor Admin as ⚙️ Administrador
    actor Recepcao as 📋 Recepcionista
    actor Medico as 👨‍⚕️ Dr. Carlos (Consultório 01)
    participant API as 🌐 API Serverless (/api/medical)
    participant DB as 🗄️ Supabase PostgreSQL
    participant TV1 as 📺 TV 01 (Térreo)
    participant TV2 as 📺 TV 02 (1º Andar)

    Admin->>API: Configura Consultório 01 -> target_tv = '1'
    Admin->>API: Configura Consultório 02 -> target_tv = '2'
    API->>DB: Grava offices com target_tv

    Recepcao->>API: Cadastra Paciente "João Silva" para Dr. Carlos (Cons. 01)
    API->>DB: Insere em patient_calls com target_tv = '1', status = 'waiting'

    Medico->>API: Clica em "CHAMAR PACIENTE"
    API->>DB: Atualiza status = 'called', called_at = NOW()
    
    par Transmissão em Tempo Real
        API-->>TV1: Evento de Chamada (target_tv: '1')
        API-->>TV2: Evento de Chamada (target_tv: '1')
    end

    Note over TV1: TV 01 detecta target_tv == '1':<br/>1. Pisca em destaque (Glow)<br/>2. Toca Chime sonoro<br/>3. Fala: "Paciente João Silva, Consultório 01"
    Note over TV2: TV 02 detecta target_tv == '1' e IGNORA:<br/>Não emite som e não altera a tela principal
```

## 4. Modelo de Dados Supabase (DDL & RLS)

```sql
-- ============================================================
-- DDL COMPLETO CMIP - ARQUITETURA MULTI-TV & CADASTRO DE MÉDICOS
-- ============================================================

-- 1. Tabela de Consultórios / Salas com TV de Destino
CREATE TABLE IF NOT EXISTS public.offices (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  code VARCHAR(20) NOT NULL UNIQUE,
  location VARCHAR(100),
  target_tv VARCHAR(20) NOT NULL DEFAULT '1', -- '1' = TV 01, '2' = TV 02, 'all' = Ambas as TVs
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Tabela de Médicos (Corpo Clínico)
CREATE TABLE IF NOT EXISTS public.doctors (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(150) NOT NULL,
  crm VARCHAR(30) NOT NULL,
  crm_uf VARCHAR(2) DEFAULT 'SP',
  specialty VARCHAR(100) NOT NULL DEFAULT 'Clínica Geral',
  phone VARCHAR(30),
  email VARCHAR(120),
  office_id BIGINT REFERENCES public.offices(id) ON DELETE SET NULL,
  office_name VARCHAR(100),
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Tabela de Usuários e Autenticação (ADMs, Recepção, Médicos)
CREATE TABLE IF NOT EXISTS public.users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(150) NOT NULL,
  username VARCHAR(50) UNIQUE NOT NULL,
  password VARCHAR(100) NOT NULL,
  role VARCHAR(30) NOT NULL CHECK (role IN ('admin', 'receptionist', 'doctor')),
  doctor_id BIGINT REFERENCES public.doctors(id) ON DELETE SET NULL,
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 4. Tabela de Pacientes
CREATE TABLE IF NOT EXISTS public.patients (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(150) NOT NULL,
  document VARCHAR(30),
  phone VARCHAR(30),
  birth_date DATE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. Tabela de Fila e Chamadas Nominais com Destino de TV
CREATE TABLE IF NOT EXISTS public.patient_calls (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  call_id INT NOT NULL DEFAULT 1,
  patient_id BIGINT REFERENCES public.patients(id) ON DELETE SET NULL,
  patient_name VARCHAR(150) NOT NULL,
  doctor_id BIGINT REFERENCES public.doctors(id) ON DELETE SET NULL,
  doctor_name VARCHAR(150) NOT NULL,
  office_name VARCHAR(100) NOT NULL,
  target_tv VARCHAR(20) NOT NULL DEFAULT '1', -- '1' = TV 01, '2' = TV 02, 'all' = Ambas
  type VARCHAR(30) DEFAULT 'Normal' CHECK (type IN ('Normal', 'Preferencial', 'Retorno')),
  status VARCHAR(30) DEFAULT 'waiting' CHECK (status IN ('waiting', 'called', 'in_progress', 'completed', 'absent', 'cancelled')),
  created_by_user VARCHAR(100),
  called_at TIMESTAMPTZ,
  finished_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. Tabela Legada de Senhas Numéricas (Totem)
CREATE TABLE IF NOT EXISTS public.tickets (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  call_id INT NOT NULL DEFAULT 1,
  number VARCHAR(20) NOT NULL,
  raw_number INT NOT NULL,
  desk VARCHAR(50) NOT NULL,
  target_tv VARCHAR(20) DEFAULT '1',
  type VARCHAR(20) DEFAULT 'Normal',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 7. Índices Estratégicos para Resposta Sub-segundo
CREATE INDEX IF NOT EXISTS idx_patient_calls_target_tv ON public.patient_calls (target_tv, status);
CREATE INDEX IF NOT EXISTS idx_patient_calls_doctor_status ON public.patient_calls (doctor_id, status);
CREATE INDEX IF NOT EXISTS idx_patient_calls_created_desc ON public.patient_calls (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_patient_calls_called_desc ON public.patient_calls (called_at DESC);
CREATE INDEX IF NOT EXISTS idx_doctors_active ON public.doctors (active);
CREATE INDEX IF NOT EXISTS idx_offices_active ON public.offices (active);
CREATE INDEX IF NOT EXISTS idx_users_username ON public.users (username);

-- 8. Row Level Security (RLS)
ALTER TABLE public.offices ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.doctors ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.users ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.patients ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Leitura Geral Offices" ON public.offices FOR SELECT USING (true);

CREATE POLICY "Escrita Geral Offices" ON public.offices FOR ALL USING (true) WITH CHECK (true);
```

```typescript
  office_name?: string;
  target_tv?: TargetTv;

  created_at?: string;

export interface UserDTO {
  id: number;
  name: string;
  username: string;
  role: UserRole;
  doctor_id?: number | null;

export interface PatientCallDTO {
  id: number;
  call_id: number;
  patient_id?: number | null;
  patient_name: string;
  doctor_id?: number | null;

  created_by_user?: string;

export interface TvStateDTO {
```

## 6. Especificação Detalhada de Componentes & Telas

### A. Painel de Administração (`src/components/AdminPanel.jsx`)
O AdminPanel será reestruturado em **4 Abas Principais**:
1. **👨‍⚕️ Corpo Clínico (Médicos)**:
   - Tabela rica com busca instantânea por Nome, CRM ou Especialidade.
   - Botão **"+ Novo Médico"** que abre modal com os campos: *Nome Completo, CRM, UF (dropdown estados), Especialidade, Telefone, E-mail, Consultório Vinculado (com indicação da TV), Switch "Criar Usuário de Acesso" (com username e senha)*.
   - Ações por linha: *Editar*, *Ativar/Desativar*, *Excluir*.
2. **🚪 Consultórios & Salas**:
   - Tabela de Consultórios com indicação visual da TV associada (`📺 TV 01`, `📺 TV 02`, `📺 Ambas`).
   - Botão **"+ Novo Consultório"** com campos: *Nome da Sala, Código/Sigla (ex: C01), Localização (ex: Térreo Ala A), TV de Destino (Dropdown: TV 01, TV 02, Ambas as TVs)*.
3. **👥 Usuários & Acessos**:
   - Gestão de contas do sistema (`admin`, `receptionist`, `doctor`), com redefinição de senhas e vínculo com o cadastro do médico.
4. **📊 Controle de Filas & Auditoria**:
   - Visão em tempo real das chamadas do dia e botão protegido de **"Zerar Filas do Dia"** com modal de dupla confirmação.

### B. Painel de Recepção (`src/components/ReceptionPanel.jsx`)
- Carrega a lista atualizada de médicos ativos (`doctors.filter(d => d.active)`).
- Ao selecionar um médico, exibe automaticamente o consultório e a TV onde a chamada ecoará (ex: *"Encaminhando para Dr. Carlos Eduardo — Consultório 01 (TV 01 - Térreo)"*).
- Seletor de prioridade tátil: **Normal** vs **Preferencial (Idoso/PCD)**.
- Adiciona o paciente instantaneamente na fila do médico com `target_tv` preenchido automaticamente a partir do consultório.

### C. Painel Exclusivo do Médico (`src/components/DoctorPanel.jsx`)
- Identifica o médico logado e o consultório ativo com sua respectiva TV de destino.
- Fila com separação visual de prioridades e contagem regressiva de espera.
- Ações:
  - 🔔 **CHAMAR PACIENTE**: Atualiza status para `called` e dispara para a TV configurada no consultório.
  - 🔄 **RECHAMAR**: Dispara novo som e voz na TV.
  - 🩺 **EM ATENDIMENTO**: Muda status para `in_progress`.
  - ✅ **FINALIZAR CONSULTA**: Marca como `completed` e libera o foco para o próximo.
  - 🚫 **MARCAR AUSENTE**: Cancela/rebaixa o registro.

### D. Painel das TVs (`src/components/TvPanel.jsx`)
- **Detecção Automática da TV**:
  - Lê parâmetro da URL: `?tv=1` ➔ TV 01 (Térreo); `?tv=2` ➔ TV 02 (1º Andar); `?tv=all` ➔ Todas.
  - Se aberta sem parâmetro, permite selecionar no menu superior e grava no `localStorage.getItem('cmip_selected_tv')`.
- **Filtro de Chamadas e Áudio**:
  - A TV 01 só insere na fila de áudio (`audioQueueRef`) e no display chamadas com `target_tv === '1'` ou `target_tv === 'all'`.
  - A TV 02 só insere na fila de áudio chamadas com `target_tv === '2'` ou `target_tv === 'all'`.
- **Motor de Áudio FIFO Imune a Travamentos**:
  - Chime sonoro estereofônico + Web Speech Synthesis em Português com fala humanizada:
    > *"Atenção: Paciente [Nome], dirigir-se ao [Consultório], Doutor(a) [Médico]"*
  - Overlay de desbloqueio com suporte a clique, toque e controle remoto Smart TV (Enter / Tecla OK).

## 8. Modelagem de Ameaças Mantis (Threat Model)

```
┌────────────────────────────┐       ┌────────────────────────────┐
│      UNTRUSTED CLIENT      │       │     TRUSTED SERVERLESS     │
│   Recepção / Médicos / TV  │ ────► │     Vercel api/medical     │
└────────────────────────────┘       └──────────────┬─────────────┘
                                                    │
                                                    ▼
                                     ┌────────────────────────────┐
                                     │     DATABASE BOUNDARY      │
                                     │     Supabase PostgreSQL    │
                                     └────────────────────────────┘
```

| ID | Ameaça / Vetor | Superfície de Ataque | Impacto | Severidade | Mitigação no Código |
|:---:|---|---|---|:---:|---|
| **SEC-01** | Chamada emitida para a TV incorreta | Parâmetro manipulado | Paciente vai para a sala errada | 🟠 Alta (P1) | O backend deriva o `target_tv` estritamente do `offices.target_tv` vinculado ao médico, ignorando sobrescrita arbitrária do client |
| **SEC-02** | Race condition de chamada simultânea | 2 médicos chamando simultaneamente | Conflito na TV e fala sobreposta | 🟠 Alta (P1) | Processamento FIFO sequencial com trava `isProcessingQueueRef` e atualização atômica de status |
| **SEC-03** | Modificação indevida de dados por não-admins | Endpoint `/api/medical` | Desconfiguração de salas ou médicos | 🔴 Crítica (P0) | Validação de credenciais e role `admin` em todas as ações de CRUD de médicos/consultórios |
| **SEC-04** | Bloqueio de Autoplay em Smart TVs | Política de áudio do navegador | TV muda visual mas não emite som | 🟠 Alta (P1) | Banner de desbloqueio persistente + gatilho em eventos universais (`keydown`, `click`, `touchstart`, `pointerdown`) |
